# 中文公开文章写作规范

本规范约束 `article-index.json` 中登记的中文公开文章。文章未发布前可以修订；进入 `published` 后，正文、发布提交和正文 SHA-256 应冻结，后续更正使用新文章和 `supersedes` 关系。

## 1. 标题与层级

1. 一级标题使用文章标题，项目品牌统一写作 `HIP-CSharp-API`，公开包使用 `JYPPX.ROCm.HIP.CSharp.API`。
2. 正文从二级标题开始编号，三级标题使用 `1.1`、`1.2` 等层级。
3. 每篇文章从“前言”开始，说明项目定位、源码仓库、核心包、Runtime 包或官方 ROCm/HIP 依赖，以及本文程序入口。
4. 不在文章末尾放置尚未发布的“下一篇”链接；后续选题只写入模块 README 或路线图。

## 2. 链接与源码

- 项目源码：`https://github.com/guojin-yan/HIP-CSharp-API`
- 核心包：`https://www.nuget.org/packages/JYPPX.ROCm.HIP.CSharp.API`
- HIP/ROCm 官方资料必须保留完整 URL、版本和访问日期。
- 示例必须标出仓库目录、入口文件和对应的最小运行命令。
- 本地路径、云端地址、SSH 端口、密钥、token 和完整用户目录不得写入公开正文。

## 3. 输出和证据

每个可执行流程都要给出输出和判定标准。必须明确区分：

- 静态检查 / 编译成功；
- 包还原 / clean consumer 成功；
- Runtime 加载成功；
- 真实 GPU 功能成功；
- 性能或重复生命周期结果。

没有真实运行证据时只能使用“期望输出”或“静态检查结果”，不得把命令帮助、符号扫描或一次云端结果扩写为支持承诺。

## 4. 图表与代码

- Mermaid 流程图优先使用 `flowchart TD`。
- 图片最大显示宽度为 `640px`，并设置 `max-width: 100%`。
- 代码必须说明 TFM、OS、GPU、ROCm/HIP 版本和 native 库来源。
- 所有拥有原生资源的代码片段都必须说明创建者、使用者和释放者。

## 5. 文章声明

每篇 ready/published 文章末尾都要包含：开源协议、AI 辅助开发说明、测试范围、平台限制、供应商依赖、免责声明和社区反馈入口。声明之后不得追加未发布文章链接。
