# 0.9.2 interface ledger validation / 0.9.2 逐接口账本验证

Core `0.9.2` is an unpublished validation batch. It does not add a managed public API and its 68 exported types and 1,002 members remain byte-equivalent to the published `0.9.1` API snapshot across all 15 TFMs.

Core `0.9.2` 是未发布的验证批次。它不新增托管公开 API；全部 15 个 TFM 的 68 个导出类型和 1,002 个成员继续与已发布 `0.9.1` API snapshot 逐字节等价。

The batch adds a deterministic 477-entry JSONL ledger generated from the pinned ROCm 7.2.1 complete model, the 100-entry managed owner manifest, and explicit reviewed disposition rules. Runtime contributes 459 declarations and HIPRTC contributes 18. The 377 declarations outside the managed owner manifest are individually classified as `managed-next`, `raw-only-reviewed`, or `deferred-capability`, with missing function and negative evidence represented as `not-tested`.

本批次新增确定性的 477-entry JSONL 账本，输入为固定 ROCm 7.2.1 complete model、100-entry 托管 owner manifest 和显式 reviewed disposition 规则。其中 Runtime 459 个声明、HIPRTC 18 个声明。托管 owner manifest 之外的 377 个声明逐项分类为 `managed-next`、`raw-only-reviewed` 或 `deferred-capability`；缺少功能或负向证据时统一记录为 `not-tested`。

Historical M8.9 evidence remains bound to exact public `0.9.1` bytes. The ledger may reference it as `passed-historical`, but never upgrades it to evidence for another SHA. A symbol export proves presence only, not function semantics. Current validation must use a clean detached checkout of the exact `0.9.2` commit and record official-host and package-only paths independently.

M8.9 历史证据继续只绑定精确的公开 `0.9.1` bytes。账本可以通过 `passed-historical` 引用它，但绝不把它升级为其他 SHA 的证据。symbol export 只证明符号存在，不证明函数语义。当前验证必须使用精确 `0.9.2` commit 的 clean detached checkout，并分别记录 official-host 与 package-only 路径。

This batch is always `publishable=false` and `releaseAuthorized=false`. It does not authorize push, tag, NuGet publication, GitHub Release, Actions, Pages, an article, or any `1.0.0` action. Windows AMD GPU validation and a separate explicit Owner release request remain mandatory for any future `1.0.0`.

本批次始终为 `publishable=false`、`releaseAuthorized=false`。它不授权 push、tag、NuGet 发布、GitHub Release、Actions、Pages、文章发布或任何 `1.0.0` 动作。未来任何 `1.0.0` 仍必须同时取得 Windows AMD GPU 实机验证和 Owner 单独明确发布指令。
