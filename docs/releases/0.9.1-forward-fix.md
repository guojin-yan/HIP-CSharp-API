# 0.9.1 assembly identity forward fix / 程序集 identity 修正

Core `0.9.1` aligns the NuGet package ID, assembly identity, DLL name, and XML documentation name as `JYPPX.ROCm.HIP.CSharp.API`. Public namespaces and API types remain under `JYPPX.ROCm.HipSharp`; no namespace, type, member, ABI, ownership, disposal, or native-runtime payload change is intended.

Core `0.9.1` 将 NuGet 包 ID、程序集 identity、DLL 文件名和 XML 文档名统一为 `JYPPX.ROCm.HIP.CSharp.API`。公开命名空间与 API 类型继续位于 `JYPPX.ROCm.HipSharp`；本修正不应改变 namespace、类型、成员、ABI、所有权、释放规则或原生 Runtime payload。

Core `0.9.0` was published with the unintended `JYPPX.ROCm.HipSharp` assembly identity. NuGet packages are immutable, so those bytes are never overwritten or republished as the same version. The decision to unlist `0.9.0` is a separate Owner-authorized external action.

Core `0.9.0` 已使用错误的 `JYPPX.ROCm.HipSharp` 程序集 identity 发布。NuGet 包不可变，因此绝不覆盖这些 bytes，也不以相同版本重新发布。是否 unlist `0.9.0` 是一项需要 Owner 单独授权的外部操作。

The M8.7/M8.8 validation evidence and `v0.9.0` tag remain historical evidence for the immutable old bytes. They do not authorize or validate `0.9.1`. Before publication, the forward fix requires clean 15-TFM build/package/API gates, a new exact commit and package hash, fresh official-host plus isolated package-only GPU validation, public-feed verification, and new push/tag/NuGet/GitHub Release authorization.

M8.7/M8.8 验证证据与 `v0.9.0` tag 继续作为旧不可变 bytes 的历史证据，但不授权或验证 `0.9.1`。发布前，forward fix 必须完成 clean 15-TFM build/package/API 门禁、新 exact commit/package hash、新 official-host 与隔离 package-only GPU 验证、public-feed 校验，以及新的 push/tag/NuGet/GitHub Release 授权。

Windows Runtime remains disabled/unverified/static-only. Single-GPU P2P must be reported as an honest skip, and no performance claim is permitted.

Windows Runtime 继续保持 disabled/unverified/static-only。单 GPU 的 P2P 必须如实记录为 skip，且不得作性能声明。
