# 0.9.1 assembly identity forward fix / 程序集 identity 修正

Core `0.9.1` aligns the NuGet package ID, assembly identity, DLL name, and XML documentation name as `JYPPX.ROCm.HIP.CSharp.API`. The corrected optional Linux Runtime ID is `JYPPX.ROCm.HIP.CSharp.API.Runtime.linux-x64` version `7.2.1`; public namespaces and API types remain under `JYPPX.ROCm.HipSharp`. No public namespace, type, member, ABI, ownership, disposal, or native-runtime payload change is intended.

Core `0.9.1` 将 NuGet 包 ID、程序集 identity、DLL 文件名和 XML 文档名统一为 `JYPPX.ROCm.HIP.CSharp.API`。修正后的可选 Linux Runtime ID 为 `JYPPX.ROCm.HIP.CSharp.API.Runtime.linux-x64`、版本 `7.2.1`；公开命名空间与 API 类型继续位于 `JYPPX.ROCm.HipSharp`。本修正不应改变公开 namespace、类型、成员、ABI、所有权、释放规则或原生 Runtime payload。

## Adapter integration note / 适配器集成说明

The current source candidate adds no HipSharp public API. It grants friend access only to `JYPPX.ROCm.MIGraphX.CSharp.API.HIP.Interop` and adds an internal atomic stream enqueue/pending-callback method so the optional adapter can retain completion cleanup without exposing raw handles. HipSharp core remains independent of MIGraphXSharp. Local substitute tests do not add an official GPU, performance, or zero-copy claim.

当前源码候选不新增 HipSharp 公开 API。它只向 `JYPPX.ROCm.MIGraphX.CSharp.API.HIP.Interop` 授予 friend access，并增加 internal 原子 stream enqueue/pending-callback 方法，使可选 adapter 无需公开裸 handle 即可保留完成清理。HipSharp core 继续独立于 MIGraphXSharp；本地替身测试不增加官方 GPU、性能或 zero-copy 结论。

Core `0.9.0` was published with the unintended `JYPPX.ROCm.HipSharp` assembly identity. NuGet packages are immutable, so those bytes are never overwritten or republished as the same version. The decision to unlist `0.9.0` is a separate Owner-authorized external action.

Core `0.9.0` 已使用错误的 `JYPPX.ROCm.HipSharp` 程序集 identity 发布。NuGet 包不可变，因此绝不覆盖这些 bytes，也不以相同版本重新发布。是否 unlist `0.9.0` 是一项需要 Owner 单独授权的外部操作。

The M8.7/M8.8 validation evidence and `v0.9.0` tag remain historical evidence for the immutable old Core and old Runtime IDs. They do not authorize or validate the corrected Core/Runtime package family. Before publication, the forward fix requires clean 15-TFM build/package/API gates, new exact package hashes, fresh official-host plus isolated package-only GPU validation, public-feed verification, and new push/tag/NuGet/GitHub Release authorization.

M8.7/M8.8 验证证据与 `v0.9.0` tag 继续作为旧 Core 与旧 Runtime ID 不可变 bytes 的历史证据，但不授权或验证修正后的 Core/Runtime 包族。发布前，forward fix 必须完成 clean 15-TFM build/package/API 门禁、新 exact package hash、新 official-host 与隔离 package-only GPU 验证、public-feed 校验，以及新的 push/tag/NuGet/GitHub Release 授权。

Windows Runtime remains disabled/unverified/static-only. Single-GPU P2P must be reported as an honest skip, and no performance claim is permitted.

Windows Runtime 继续保持 disabled/unverified/static-only。单 GPU 的 P2P 必须如实记录为 skip，且不得作性能声明。
