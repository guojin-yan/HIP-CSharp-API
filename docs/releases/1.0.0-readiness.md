## Route decision

Decision dated 2026-08-15: Linux Core `1.0.0` may proceed while Windows M7 remains deferred. This follows the Definition of Done rule that an unvalidated Windows Runtime can be excluded without blocking Linux Core. The required guardrail is explicit: Windows Runtime stays `disabled/unverified/static-only`, and Core compilation on Windows is never described as Windows GPU/runtime validation.

## Current conclusion

The local DoD has no identified public-contract, Linux usability, license or supply-chain design blocker. Candidate-specific local rows must be rebound after the clean commit. The external exact-package official-host and isolated package-only GPU rows cannot be closed without new Owner authorization; until then the maximum state is `blocked-pending-exact-package-gpu-validation` after `candidate-built`.

The historical `eng/test-promotion.ps1` positive fixture intentionally depends on M8.9 bundle and candidate-package bytes removed by the controlled cleanup. It now fails closed on the missing fixture and is not regenerated or repointed: doing so would rewrite historical evidence. The immutable M8.9 receipt remains checked by project-quality and Runtime supply-chain tests; neither that receipt nor its mutation test authorizes `1.0.0` bytes.
