# 0.9.0 Linux release candidate / Linux 发布候选

`JYPPX.ROCm.HIP.CSharp.API` version `0.9.0` is a local release candidate for public API freeze review. It is not a published stable release. The optional Linux runtime candidate remains `JYPPX.ROCm.HipSharp.Runtime.linux-x64` version `7.2.1` and is also unpublished.

`JYPPX.ROCm.HIP.CSharp.API` `0.9.0` 是用于公开 API 冻结审查的本地发布候选，并非已发布稳定版。可选 Linux runtime 候选仍为 `JYPPX.ROCm.HipSharp.Runtime.linux-x64` `7.2.1`，同样未发布。

This candidate adopts the pre-release `JYPPX.ROCm.HipSharp` namespace and assembly identity. The former namespace baseline is intentionally invalidated; no compatibility namespace, facade, forwarding assembly, or legacy package is produced. See the [migration decision](../design/jyppx-rocm-naming-migration.md).

本候选采用发布前冻结的 `JYPPX.ROCm.HipSharp` 命名空间与程序集标识。原 namespace baseline 明确作废，不生成兼容 namespace、facade、类型转发程序集或旧包。参见[迁移决策](../design/jyppx-rocm-naming-migration.md)。

The committed API snapshot is checked against all 15 target frameworks. The selected managed owners are driven by a 100-entry interop manifest: 91 HIP Runtime and 9 HIPRTC entries. M8.6 adds `hipModuleGetGlobal` for borrowed byte/typed module symbol views after M8.5's six module-kernel entries. The complete low-level model remains 459 HIP Runtime and 18 HIPRTC C ABI declarations from the pinned official headers; 368 Runtime and 9 HIPRTC declarations remain low-level-only. The formal/diagnostic/sample-only/internal classification, ownership and disposal rules, thread-safety limits, error model, and permitted pre-freeze changes are recorded in the [API freeze review](../guides/api-freeze.md).

Local candidate requirements are fail-closed:

- one central version source for Core `0.9.0`, Linux Runtime `7.2.1`, and the disabled Windows Runtime `7.2.0` skeleton;
- deterministic interop generation from the 100-entry owner manifest plus the pinned-header complete model, with identical public API on all TFMs;
- build, unit, quality, package, clean-consumer, documentation, source-provenance, closure, license, SBOM, size, and static Windows gates;
- exact Git commit metadata in both packages and a clean-SHA runtime-candidate attestation;
- `publishable=false` until the exact Core and Runtime packages pass a newly Owner-authorized isolated host and PRoot GPU gate.

The M8.1 Radeon Cloud result at `e78854f` remains historical evidence for all 477 low-level symbols and the previous managed surface. It does not validate the M8.2-M8.6 managed entry paths, a newly built 0.9.0 Core package, or a runtime package bound to a different commit. M8.7 supplies a fixed HIPRTC integration workload with independent M8.2-M8.6 JSON results, managed negatives, CPU/GPU oracles, and official-host/package-only gate integration. Local self-tests prove only serialization, aggregation, failure propagation, source boundaries, and compilation. No newly authorized real 100-entry symbol, schema-7 ABI, Runtime, module-symbol, graph, occupancy/cooperative, loader-map, or GPU result exists yet. Windows remains disabled, inventory-empty, static-audit-only, and GPU-unvalidated. No support breadth or performance claim is made.
