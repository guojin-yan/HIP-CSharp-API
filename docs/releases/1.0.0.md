# 1.0.0 Linux Core candidate / Linux Core 候选

Status: **candidate, unpublished**. Local construction, GPU validation, release authorization and publication are four separate states. This document does not grant any external action.

状态：**候选，尚未发布**。本地构建、GPU 验证、发布授权和实际发布是四个独立状态；本文件不授权任何外部动作。

## Scope / 范围

- Package and assembly identity: `JYPPX.ROCm.HIP.CSharp.API`; public namespace: `JYPPX.ROCm.HipSharp`.
- Managed-only Core with no AMD driver, ROCm native payload, code object, runtime-package hard dependency, credential, cloud evidence or local absolute path.
- The public surface is frozen at 68 exported types and 1,002 members across all 15 TFMs and is semantically identical to published Core `0.9.1`.
- Generated low-level coverage remains 459 HIP Runtime and 18 HIPRTC declarations. The selected managed owner manifest remains 91 Runtime and 9 HIPRTC entries.
- The optional public Linux Runtime remains independently versioned at `7.2.1`; consumers may instead use a compatible system ROCm installation.
- Windows Runtime remains disabled/unverified/static-only and is not a Linux Core exit blocker. Core build compatibility does not imply Windows GPU/runtime support.

## Compatibility boundaries / 兼容边界

The package retains all 15 TFMs: `net46` through `net481`, `netcoreapp3.1`, and `net5.0` through `net10.0`. EOL targets remain compatibility assets and do not imply upstream security support. Ownership, disposal ordering, error normalization, enum values, default values, ABI and TFM parity do not change from `0.9.1`.

P2P is capability-dependent and remains `skipped(device-count<2)` in the latest one-device evidence. Samples and reliability gates validate correctness and bounded lifecycle behavior; they are not benchmarks and support no performance claim. NativeAOT, arm64, graphics/external interop expansion, new HIP features and Windows M7 are outside this candidate.

## Candidate gate / 候选门禁

The exact clean-SHA nupkg must pass 15-TFM Release build, tests, public API equality, package audit, `net46`/`netcoreapp3.1`/`net7.0`/`net10.0` consumers, system-native Core-only audit, public Runtime `7.2.1` pairing audit, source/supply-chain/Windows static gates, clean DocFX generation, normalized package comparison and sensitive-data scans. The pairing audit uses NuGet package source mapping so both JYPPX packages can only resolve from the exact local candidate feed; nuget.org is allowed only for Microsoft framework/host packs needed by the cross-RID build.

Historical M8.9 evidence proves the published `0.9.1`/`7.2.1` pair, not the new Core bytes. Before this candidate becomes `candidate-validated`, the exact Core hash must pass a newly Owner-authorized official-host and isolated package-only GPU/ABI run. Even then `publishable=false` and `releaseAuthorized=false` remain until a separate Owner release instruction.

The exact SHA, package size/hash and content-attestation identity are recorded only after the clean candidate commit and are referenced from the [readiness matrix](1.0.0-readiness.md).
