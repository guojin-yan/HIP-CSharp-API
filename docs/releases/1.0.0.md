# 1.0.0 Core candidate / Core 发布候选

Status: **under validation, unpublished**. This is the candidate for the current 122-type / 1,372-member API, across all 15 declared target frameworks. The earlier August candidate is preserved in [the historical record](1.0.0-2026-08.md); it is not the active API baseline.

状态：**验证中，未发布**。版本号确定为 1.0.0，但版本号、构建成功和发布批准不是同一件事。所有通过结果必须绑定实际测试的提交、包哈希和宿主。

## Package contract / 包的边界

Core `JYPPX.ROCm.HIP.CSharp.API` contains managed assemblies, bilingual XML documentation, README, logo and Apache-2.0 license. It has no native payload or mandatory Runtime dependency. Public namespaces remain `JYPPX.ROCm.HipSharp`.

The generated low-level model contains 459 Runtime and 18 HIPRTC declarations. The managed interface ledger contains 239 entries; 238 entries remain explicitly raw-only. An export scan or a successful sample does not establish functional coverage of every entry.

Core 1.0.0 and native Runtime versions are independent. The immutable public Ubuntu Runtime stays 7.2.1. Local Windows/Ubuntu 10.1.0 Runtime packages retain their `10.1.0-local.*` identities and redistribution limitations; they are not renamed 1.0.0 or automatically approved for public redistribution.

### Upstream limitations / 上游限制

The Core release uses the official Runtime interface and does not carry private
AMD source patches. Confirmed upstream defects are deferred while AMD investigates
or releases corrections. See the [upstream Runtime issue register](../guides/upstream-runtime-issues.md)
for affected versions and official tracking links. In particular, affected typed
2D fills, driver bitcode linking, Windows batch operations, external-semaphore graph
nodes, primary-context lifecycle assumptions and legacy border-color operations
are not qualified as working functionality. Windows external-semaphore graph APIs
can terminate the process on the affected Runtime and must not be used there.

This is a managed Core release, not a guarantee that every exposed native function
works on every AMD Runtime. The separate local Runtime packages remain test
dependencies with unresolved public redistribution requirements. Native defects do
not require HipSharp to build a patched AMD Runtime before releasing managed fixes;
they still remain failures in test records and explicit support exclusions.

本次按托管 Core 的支持范围准备发布，已确认的 AMD 原生缺陷等待官方修复；
项目不携带或维护 AMD 私有补丁，不把受影响接口算作实测通过，也不宣称所有
接口可用。本地 Runtime 包的公开再分发条件与 Core 的发布条件分别审查。

## Changes / 修复

- Preserve the 122-type / 1,372-member API baseline from the previous development version, with identical signatures across all TFMs.
- Keep versioned Windows HIPRTC discovery correct in no-RID, flattened RID/apphost and .NET Framework 4.8 deployments.
- Bind each loaded native filename to its own package hash; reject unknown HIP closures, paths outside the consumer, symlinks and junctions.
- Reject extra candidate files, duplicate JSON keys and ambiguous Windows/Linux archive paths before extraction.
- Reject `RetainPhysicalMemory` on HIP before 7.12 before invoking native retain. These runtimes have a known missing-reference defect that can crash when both owners are released. Keep the original allocation alive through all mappings instead. The raw API remains an explicit native boundary and does not acquire managed safety guarantees.
- Support an offline framework feed using `HIPSHARP_SUPPORT_FEED` for clean consumer audits; HipSharp packages remain restricted to the exact candidate feed.
- Treat POSIX shareable descriptors as signed 32-bit values, accept descriptor zero, reject invalid ranges and preserve native errors. Add Linux KFD physical-memory sharing and cross-process memory/event IPC fixtures.
- Reject default/null descriptors at managed interop entry points, check callback Runtime/stream disposal and capture state, and reject graphics null-success results.
- Preserve owner cleanup retry after the last borrow fails, return all borrows during failed submission rollback, and release stream ownership even when graphics rollback fails.

## Required validation / 验证要求

Use a clean commit and keep every build output outside source. Run the full managed test/build/API/package gates on Windows and Linux; then test the same Core nupkg with the local Windows and Ubuntu runtimes and the fixed public Ubuntu 7.2.1 package. Include RID dotnet/apphost, Windows net48, missing-HIPRTC, filename/hash swaps, candidate tampering, native symbols/ABI, reliability, and documentation clean generation.

The exact 1.0.0 Core from `3d626ddf643e1bfef3a358ea3e26c3e5fedcdf38` passed the enhanced 24-case package matrix with both public 7.2.1 and local .3 Runtime packages on Ubuntu 24.04/KFD/gfx1100. Both also passed 24 isolated PRoot deployments without the system HIP SDK. The new IPC and physical-memory fixtures passed; the public Runtime safely rejected managed retain on a real mapping, while .3 verified independent-owner release. Windows and WSL passed their standard package/deployment matrices with explicit capability skips. These results do not establish full function-level coverage or native redistribution approval.

Cloud evidence has been recovered locally, including the earlier native retain AddressSanitizer failure and its passing no-retain control. The instance is no longer needed for the completed checks. See the readiness matrix for exact package identity, limitations and remaining release gates.

The [readiness matrix](1.0.0-readiness.md) lists open gates. Publication remains blocked while applicable gates are open. No tag, GitHub Actions publication, NuGet upload or GitHub Release is authorized by this document.
