# 0.9.3 Known Limitations / 0.9.3 已知限制

## `hipMemRetainAllocationHandle` on ROCm 7.2.1

The pinned ROCm 7.2.1 runtime has an upstream defect in
`hipMemRetainAllocationHandle`. The function returns the same generic-allocation
pointer as the original owner without acquiring the additional native reference
required by the API contract. Releasing both managed owners can therefore enter
the ROCm reference-release path with an already-destroyed object and terminate the
process inside `libamdhip64.so`.

This is not a C# declaration or `SafeHandle` ordering defect. The native control
sequence and the generated low-level calls are stable, while the high-level
retained-owner sequence reproduces the failure on the fixed 7.2.1 runtime. The
official ROCm CLR repair adds the missing `ga->retain()`; that repair is not part
of the pinned runtime package used by this release candidate.

The managed API remains exposed for callers that need the direct HIP contract, but
applications should avoid the retained-allocation path on ROCm 7.2.1. Do not work
around the issue by suppressing the second release: that leaks a native reference.
Use a ROCm build containing the upstream fix when this operation is required.

The limitation and the exact cloud evidence are recorded in
`Radeon_Cloud/records/20260817-201423-8a55157-m8.15-incomplete/`. It is a runtime
limitation, not a reason to misclassify unrelated API, package, or HIPRTC tests.

## ROCm 7.2.1 上的 `hipMemRetainAllocationHandle`

固定使用的 ROCm 7.2.1 runtime 在 `hipMemRetainAllocationHandle` 中存在上游缺陷：
函数返回与原始 owner 相同的 generic-allocation 指针，却没有按 API 契约增加第二个
原生引用计数。于是两个托管 owner 按契约分别释放时，第二次释放可能在
`libamdhip64.so` 的内部引用释放路径访问已销毁对象并终止进程。

这不是 C# 声明或 `SafeHandle` 释放顺序问题。原生控制序列和生成的低层调用稳定，
而固定 7.2.1 runtime 上的高层 retained-owner 序列可以稳定复现该故障。官方 ROCm
CLR 修复增加了缺失的 `ga->retain()`；本候选使用的固定 runtime 包不包含该修复。

托管 API 仍保留，以便调用方直接使用 HIP 契约，但在 ROCm 7.2.1 上应避免 retained
allocation 路径。不要通过跳过第二次释放来规避，这会泄漏原生引用；需要该操作时应
使用包含上游修复的 ROCm 构建。

限制和精确云端证据记录在
`Radeon_Cloud/records/20260817-201423-8a55157-m8.15-incomplete/`。这是 runtime
限制，不应影响其他接口、包审计或 HIPRTC 测试的独立结论。
