# 0.10.0 Release / 0.10.0 发布说明

Core `0.10.0` releases the managed HIPRTC Program/Linker expansion and the current
runnable tutorial and showcase documentation set. The Core package remains
dependency-free and provides the same 15 target-framework asset groups from
`net46` through `net10.0`.

Core `0.10.0` 发布 HIPRTC Program/Linker 托管扩展，以及当前可运行教程和综合案例的
文档集合。Core 包仍然不含 NuGet 依赖，并继续提供从 `net46` 到 `net10.0` 的 15 组目标
框架资产。

## Validation / 验证

The release gate requires a clean exact source commit and package hash. It covers
the 15-TFM build and package audit, clean consumers, the Runtime and HIPRTC symbol
checks, the HIPRTC Program/Linker lifecycle workload, device and memory workloads,
stream/event and advanced-feature workloads, M8.2-M8.6 managed expansion with
1,127 CPU/GPU comparisons, and the bounded 10-round/four-stream reliability run.
The isolated package-only path also verifies native-loader closure and rejects
missing, Core-only, tampered, and mixed-runtime negative configurations.

发布门禁要求干净的精确源码提交和包哈希。它覆盖 15 TFM 构建与包审计、干净消费者、
Runtime/HIPRTC 符号检查、HIPRTC Program/Linker 生命周期 workload、设备与内存 workload、
Stream/Event 与高级功能 workload、M8.2-M8.6 的 1,127 次 CPU/GPU 比较，以及有界的
10 轮/4 stream 可靠性运行。隔离 package-only 路径还会验证原生加载闭包，并拒绝缺依赖、
仅 Core、篡改包和混合 Runtime 的负向配置。

## Compatibility / 兼容性

The optional Linux Runtime package remains version `7.2.1` and is independently
versioned. Windows AMD GPU validation is still not available and remains mandatory
before a future `1.0.0` release.

可选 Linux Runtime 包仍为独立版本的 `7.2.1`。Windows AMD GPU 实机验证仍不可用，
在未来 `1.0.0` 发布前仍是必须满足的条件。

## Known Limitation / 已知限制

On ROCm 7.2.1, `hipMemRetainAllocationHandle` has an upstream reference-counting
defect. It remains exposed as the direct HIP contract, but applications should not
use the retained-allocation ownership path until their ROCm build includes the
upstream `ga->retain()` repair. Suppressing the second release is not a workaround,
because it leaks a native reference.

在 ROCm 7.2.1 上，`hipMemRetainAllocationHandle` 存在上游引用计数缺陷。该接口继续
按直接 HIP 契约公开；但在所用 ROCm 构建包含上游 `ga->retain()` 修复前，应用不应使用
retained-allocation 所有权路径。跳过第二次释放不是可接受的规避方式，因为会泄漏原生引用。
