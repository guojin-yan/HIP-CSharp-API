# Linux runtime package audit / Linux runtime 包审计

`JYPPX.ROCm.HIP.CSharp.API` remains managed-only and can use a system ROCm installation. The optional `JYPPX.ROCm.HipSharp.Runtime.linux-x64` package is a separate ROCm 7.2.1 user-mode closure. M5 enabled a guarded verified historical package after isolated validation; M8.1 generates a new, exact-SHA, explicitly unverified and non-publishable candidate for the 0.9.0 Core pair.

The source lock accepts only AMD's signed Ubuntu Noble repository. `prepare-runtime.ps1` checks the pinned archive-key fingerprint, `InRelease`, `Packages.gz`, six Debian packages, canonical ELF metadata, file hashes, component licenses, closure boundaries, and CycloneDX hash. It stages only HIP Runtime, HIPRTC/builtins, HSA Runtime, COMGR, rocprofiler-register, loader/SONAME aliases, licenses, manifest, and SBOM. Headers, compilers, static libraries, debug symbols, rocminfo executables, rocm-core scripts, kernel drivers, and device nodes are forbidden.

NuGet ZIP extraction does not retain Debian symlinks. The allowlist therefore stores the versioned payload and only the generic/SONAME names needed by the managed loader or ELF/dynamic lookup as identical hashed files. All packaged ROCm libraries use `$ORIGIN` RPATH. The managed loader rejects package/system or two-directory Runtime/HIPRTC mixing.

The payload is 415,070,520 unpacked bytes. Under the former package ID, the historical validated candidate was 162,891,900 bytes and the historical verified final package was 162,892,126 bytes. Those values support the single-package topology below the 262,144,000-byte gate, but they do not verify the renamed package. A new external package audit must record the renamed exact nupkg size and SHA-256 without introducing a self-reference into the embedded manifest.

The M5 candidate and final gates ran on newly authorized isolated GPU consumers with the AMD kernel driver and `/dev/kfd`/`/dev/dri`, but no `/opt/rocm`, system `libamdhip64`, system `libhiprtc`, staging path, or source-derived native file. Loader traces, `readelf`, `ldd`, process maps, symbols, DeviceInfo, MemoryCopy, HIPRTC VectorAdd, and the two-stream/event VectorAdd all resolved through the NuGet extraction directory. Missing HSA, core-only, tampered-package, and mixed-directory negatives failed closed. M6 later repeated that immutable package as a historical regression with all 46 Runtime and 9 HIPRTC exports plus the advanced workload.

Those historical results are not promotion evidence for a new candidate. `pack-runtime.ps1 -Candidate` now binds the current clean Git SHA, Core version, source manifest, candidate manifest, SBOM, and full staging digest. The resulting manifest has `verified=false`, the package audit reports `publishable=false`, and the exact Core/Runtime pair must pass newly authorized host and PRoot gates before any release decision.
