# M8.7 Linux managed expansion validation design

M8.7 adds an integration workload and evidence contract. It does not add Core public API. The
workload uses only the public managed surface completed in M8.2 through M8.6 and is intended to run
unchanged on an official ROCm host and in the package-only Ubuntu Base + PRoot consumer.

## One workload, five independently reported stages

`HipManagedExpansionValidation` emits one compact JSON object with schema version 1. The object has
an overall `status`, `failureStage`, `failureIndex`, total comparisons, `performanceClaim=false`, and
an ordered result for each of M8.2 through M8.6. Each stage result records `passed`, `skipped`, or
`failed`, its own comparison count, iteration count, capability classification, managed-negative
result, failure index, and capability subtests.
The overall status is failed when any stage fails; a successful process cannot hide a failed stage.

Only these skips are valid:

- the M8.3 pool stage may skip when a pool operation returns `HipError.NotSupported`;
- the M8.4 graph-memory-node subtest may skip when that optional export returns NotSupported, while
  the regular explicit graph must still pass;
- cooperative launch may skip only when the typed device capability is false.

All other HIP errors fail the corresponding stage. In particular, an available cooperative device
whose cooperative export or launch fails is a failure. A `--self-test` mode loads no HIP library and
checks serialization, pass/skip aggregation, and failure propagation with synthetic stage results.

## Deterministic HIPRTC module

The workload compiles one fixed source with the explicitly supplied `gfx*` architecture. It exports
`Transform`, `ApplyGlobals`, `CooperativeTransform`, `validation_values`, and `validation_bytes` with
C linkage. Input arrays use fixed arithmetic sequences. Every GPU output is compared element by
element with a CPU oracle; the JSON contains counts and the first mismatch index, never timing.

`validation_values` is a 16-element `int` module global and `validation_bytes` is a 16-byte global.
The module-global stage writes both through `HipModuleGlobal<T>`/`HipModuleGlobal`, launches
`ApplyGlobals`, and checks that the kernel sees the same values. It never calls the Runtime
compiler-symbol APIs.

## M8.2 pitched memory

The stage uses a non-power-of-two 7 by 5 `int` allocation and a 5 by 3 by 2 allocation. It verifies
typed zero, synchronous and explicit-stream array round trips, and a 3D subregion whose surrounding
elements retain a byte sentinel. The CPU oracle therefore checks row pitch, slice pitch, region
offsets, and boundaries rather than merely checking that calls return. An undersized host buffer is
the managed negative and must be rejected before a HIP copy.

## M8.3 memory pool

The stage creates a custom pool for the current device with fixed release and reuse policy, reads the
policy back, queries same-device access, enters a current-pool scope, and proves that default/current
views remain borrowed. A stream-ordered allocation performs H2D/D2H round-trip comparison, is freed
on its allocation stream, and is followed by statistics reset and `TrimTo(0)`. Zero-byte allocation
is the managed negative. NotSupported is recorded with the exact managed operation and skips only
this stage; any other error fails it.

## M8.4 explicit graphs

The required graph uses regular owned device memory and an explicit memset -> copy -> kernel DAG.
It verifies topology, upload, three or more launches, and every replay result. A self-dependency is
the managed negative. A second graph adds graph-local allocation, copy, kernel, and exactly one free
node. Only this graph-memory subtest may report an export-driven NotSupported skip. Captured graphs
remain historical regression evidence and do not substitute for the explicit DAG.

## M8.5 attributes, occupancy, and cooperative launch

The stage queries typed function attributes and an occupancy plan, checks positive required resource
values and non-negative backend version/resource values,
and verifies the plan's multiprocessor count and resident-block product against typed device facts.
Zero block size is the managed negative. If cooperative launch is supported, a one-block launch uses
the same deterministic transform and must match the CPU oracle. Capability false produces an exact
subtest skip. Occupancy is resource/legality evidence only and is never a performance claim.

## M8.6 module globals and lifetime

The stage checks exact global names and extents, then performs managed-array, pinned-memory, and owned
device-memory sync/async round trips. `ApplyGlobals` proves kernel visibility. A second module submits
an async global copy, is disposed before stream completion, and must still produce the expected host
data after synchronization, proving pending module retention. An oversized typed destination is the
managed range negative.

## Trust and evidence boundaries

On the official host, locked headers, the complete 477-entry model, the 100-entry owner manifest,
and schema-7 ABI executable are SDK/ABI evidence. In Ubuntu Base + PRoot, `/opt/rocm` and system HIP
libraries must be hidden; readelf, ldd, and process maps must resolve user-mode ROCm libraries from
the exact Runtime package extraction. The exact Git SHA, Core and Runtime package hashes, result
JSON, and loader evidence must agree across both paths.

Cloud discovery of a code defect invalidates the SHA, Core package, and both result sets. The repair
must return to local full validation, create a new clean commit/package, obtain fresh transfer
authorization, and restart both remote paths. Without current Owner authorization, local work ends
with a blocked handoff and no inherited symbol, Runtime, or GPU claim.
