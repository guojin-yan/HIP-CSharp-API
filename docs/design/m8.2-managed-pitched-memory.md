# M8.2 managed pitched memory design

This feature keeps raw HIP pointers and native copy structures below the managed boundary.

- `HipRuntime.GetMemoryInfo` converts `hipMemGetInfo` outputs into an immutable `HipMemoryInfo` value.
- `HipPitchedDeviceMemory<T>` exclusively owns the pointer returned by `hipMallocPitch` or
  `hipMalloc3D`. Both allocation paths use the existing `hipFree` SafeHandle release contract.
- `HipMemoryExtent`, `HipMemoryOffset`, and `HipMemoryRegion` are immutable. Their dimensions and
  offsets are measured in `T` elements. Row pitch, slice pitch, allocation length, and pinned-buffer
  offsets are explicitly measured in bytes.
- A synchronous operation borrows device and host storage only until the native call returns. An
  asynchronous operation adds SafeHandle references for every device or pinned owner, or pins a
  managed array, and transfers a release lease to the stream. Synchronize, a successful completion
  query, or stream disposal releases those leases. Graph capture transfers the same leases to the
  resulting graph owner.
- Allocations and streams record their creation device. Calls reject another runtime client, a
  different device, a stream created on another device, or a disposed object before invoking HIP.
- Explicit disposal is idempotent and reports `hipFree` failures through `HipException`. A pending
  asynchronous lease delays release. SafeHandle final release never throws.
- The managed API covers pitched linear device allocations and tightly packed managed or pinned host
  storage. HIP arrays, symbols, legacy driver-copy structures, batch copies, peer 3D copies, and
  arbitrary raw-pointer combinations remain available only through the low-level API for later,
  separately designed feature families.

The complete workflow is memory-info query, 2D or 3D allocation, byte-pattern fill (including typed
zero), synchronous or stream-ordered H2D/D2D/D2H copy, stream completion, and deterministic disposal.
