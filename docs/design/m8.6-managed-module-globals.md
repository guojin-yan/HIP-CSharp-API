# M8.6 managed module globals and borrowed device ranges

## Identity and ownership

`HipModule.GetGlobal` resolves a UTF-8 name with `hipModuleGetGlobal` and returns a
`HipModuleGlobal` byte view. `HipModule.GetGlobal<T>` wraps the same borrowed range in an
element-oriented `HipModuleGlobal<T> where T : unmanaged`. A view retains its `HipModule` managed
owner, but it is not `IDisposable` and has no `SafeHandle`: the address belongs to the loaded code
object and must never be passed to `hipFree`. Disposing the module immediately makes every view
unusable. A later module load, even with the same code object and symbol name, creates a different
identity; an old view is never rebound to it.

The query runs entirely inside `HipModule.Invoke`, which serializes it with module disposal. Native
success is accepted only when both the device pointer and byte extent are nonzero, the `size_t`
extent is representable by the current process, and the complete address range does not wrap.
Invalid success output fails closed with `InvalidOperationException`. A native error is translated
by `HipCall`; a missing optional export therefore becomes `HipError.NotSupported` and never falls
back to compiler-symbol APIs.

## Names and typed extents

Names reject null, empty, whitespace-only, and embedded-null strings before native dispatch. The
production adapter uses the existing `Utf8NativeString` path used by module kernel lookup; no
platform-default encoding or handwritten unmanaged buffer is introduced.

The byte view exposes its extent in bytes. A typed view is created only when `ByteLength` is exactly
divisible by `sizeof(T)`, and exposes the quotient as `ElementCount`. Array lengths, offsets, counts,
element-to-byte multiplication, offset-plus-count addition, and native pointer addition are all
checked. Empty operations are allowed at the end of a range and perform no native call.

## Copy model

Host-to-symbol and symbol-to-host copies use the existing `hipMemcpy`/`hipMemcpyAsync` entries with
`HostToDevice`/`DeviceToHost`. Symbol-to-owned-device and owned-device-to-symbol copies use
`DeviceToDevice`. The borrowed symbol address is never wrapped in `HipDeviceMemory`; internal range
helpers operate on it only while the owning module is held. Public overloads accept managed arrays,
`HipPinnedMemory`, or `HipDeviceMemory`, never an arbitrary `IntPtr`.

Synchronous managed-array copies pin only for the native call. Explicit-stream array copies pin the
array until stream completion. Pinned-memory copies retain the pinned owner, and device copies
retain the allocation owner. Every asynchronous submission first acquires a module async reference
and any host/device owner references, calls native, and transfers one retryable lease to the stream
only after native success. Native failure registers no pending lease and releases everything already
acquired. If lease cleanup fails, `HipAsyncLease` keeps its release action and `HipStream` keeps the
lease, so a later `Query`, `Synchronize`, or stream `Dispose` can retry without double release.

There is deliberately no default-stream asynchronous overload: this codebase has no default-stream
owner that can expose completion and drain pending pin/module leases. Synchronous overloads use the
ordinary default HIP call and complete before returning.

## Runtime, device, and concurrency rules

Every copy requires the module device to be current before native copy dispatch. An explicit stream
must belong to the same `IHipNativeApi` identity and device ordinal. Pinned and device owners must
belong to that Runtime; device allocations must also match the module device. Disposed modules,
streams, pinned buffers, and device allocations fail before native copy. Module query/copy pointer
access is performed through `HipModule.Invoke`, so a view operation and module disposal cannot race
past one another. Pending operations hold an additional module reference, allowing a requested
module disposal to delay unload until completion; successful cleanup unloads at most once.

## Kernel arguments and retained low-level APIs

M8.6 does not add `HipKernelArgument.DevicePointer(HipModuleGlobal)`. The current pointer-owner
contract proves Runtime/device/stream ownership but not exact module identity. Accepting a borrowed
global under that contract would incorrectly allow a symbol from another module in the same Runtime
and device. A later API may add this only with an explicit same-module identity contract and launch
lease proof.

`hipGetSymbolAddress`, `hipGetSymbolSize`, `hipMemcpyFromSymbol`,
`hipMemcpyFromSymbolAsync`, `hipMemcpyToSymbol`, and `hipMemcpyToSymbolAsync` continue to represent
compiler-time `const void* symbol` identities and remain low-level-only. Module texture/surface
references, linker APIs, raw global pointers, arbitrary pointer arithmetic, IPC, and external memory
also remain outside this managed family.

## Evidence boundary

Local fake-native, generator, ABI-source, 15-TFM, public-API, DocFX, and clean-package gates prove the
managed design and marshaling only. Real `hipModuleGetGlobal` export, Runtime behavior, module-symbol
contents, and GPU execution remain pending a separate Owner-authorized environment. Historical cloud
endpoints or evidence are not inherited.
